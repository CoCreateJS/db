# Direct CoCreateDB and MongoDB operation latency

Seed documents: 1000. Subsequent samples per operation: 3.
First-call latency is reported separately. Subsequent average is the arithmetic mean of only the subsequent calls.
CoCreateDB calls use in-process db.send() with no HTTP, Socket, or CRUD server routing. MongoDB calls use the Node driver directly; driver/server communication remains included.
CoCreateDB disk mode is seeded, closed, and reopened before measurement; its OS page cache is not forcibly evicted. MongoDB data is seeded before measurement and may be warm in WiredTiger/OS cache.
