# Direct CoCreateDB and MongoDB operation latency

Seed documents: 1000. Subsequent samples per operation: 3.
First-call latency is reported separately. Subsequent average is the arithmetic mean of only the subsequent calls.
CoCreateDB calls use in-process db.send() with no HTTP, Socket, or CRUD server routing. Its foreground responses reflect local memory state; peer delivery and disk persistence are separate background work.
MongoDB calls use the Node driver directly; driver/server communication remains included. MongoDB memory acknowledgment uses explicit {w:1,j:false}; journal acknowledgment uses {w:1,j:true}.
CoCreateDB write-behind creates also check _id uniqueness through the local index/read path; this is part of the current foreground create timing.
CoCreateDB deferred flush timing is reported separately. db.flush() waits for pending index work and the deferred filesystem-write queue; it does not request fsync/crash durability. MongoDB j:true waits for on-disk journal acknowledgment.
